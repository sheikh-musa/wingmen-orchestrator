## What this is

`scripts/ci_bootstrap_schema.py` gives CI an ephemeral, fully-migrated local
PostgreSQL 17 cluster, replacing a prior 601-test skip-for-lack-of-a-live-database
gap. `up` replays `schema.sql`, then `supabase/migrations/*.sql`, then
`migrations/*.sql` (sorted by filename, 85 numbered files through `090`) against a
disposable local cluster, routing around:

1. a platform-object shim (`auth.role()`/`auth.jwt()`/`auth.uid()`, `console_readonly`
   role, etc.) for roles/schemas/extensions a vanilla Postgres lacks.
2. a "bedrock" of tables/views/functions/columns referenced throughout the committed
   migration chain but never `CREATE`d anywhere in it — hand-created against the live
   substrate before migration tracking existed. Captured read-only via
   `pg_dump`/`pg_get_functiondef` against the live orchestrator substrate (project ref
   `tscuymavysscrvoberrr`) into `migrations/infra/bedrock_substrate_core.sql` (applied
   before `schema.sql`) and `migrations/infra/bedrock_substrate_deferred.sql` (applied
   after the full `migrations/*.sql` walk, for objects that forward-reference something
   the real chain creates later).

## Key findings surfaced (queued for cc-orchestrator/cai triage, not fixed beyond what
the bootstrap itself required)

- **qa_findings dual-design**: `schema.sql`'s `create table if not exists qa_findings`
  used a `repo_name`/`title`/`description`/`source` shape that was never applied to the
  live substrate — the live table is a role/flow/pass-fail-flaky shape (predates
  migration tracking). `nervous_system/qa_bridge.py` is written against the
  `repo_name`/`title` shape and is bridging into columns that don't exist live,
  silently swallowed by its own try/except every ~5 min.
- **strategic_decisions** was missing ~18 live columns (`domain`, `decided_at`,
  `decided_by`, `superseded_by`, `audit_tier` NOT NULL no-default, `constraints`,
  `updated_at`, `is_test`, `cai_session_id`, `posted_by_identity`,
  `decided_by_verified`, `parent_msg_id`, etc.) and a `UNIQUE(decision_ref)` constraint
  required by a later migration's FK — none were ever added in `schema.sql` or any
  committed migration. Backfilled faithfully to the live shape in `schema.sql`.
- **An entire untracked HR/org-membership auth subsystem**: `auth_user_org_ids()`,
  `auth_user_org_ids_with_role(text)`, `auth_user_org_ids_with_roles(text[])`,
  `auth_user_hr_employee_id()`, `handle_new_user()`, `sync_org_memberships_to_jwt()` —
  all SECURITY DEFINER, zero migration tracking, discovered via migration 058's
  `ALTER FUNCTION` targets.
- **`hr_employees` is dead-on-production**: `auth_user_hr_employee_id()` (LANGUAGE sql)
  has referenced a table that does not exist anywhere, including live, since at least
  migration 058 — a permanently-broken function body sitting live.
  - Methodology note: LANGUAGE sql bodies are parsed/planned at `CREATE FUNCTION` time
    (needed for inlining), unlike LANGUAGE plpgsql bodies, which are opaque strings not
    validated until first CALL. This is why the bootstrap needed
    `SET LOCAL check_function_bodies = false` scoped around just this one capture
    (matching `pg_dump`'s own preamble convention) instead of fabricating a table that
    exists nowhere.
- **`bulk_insert_morphology(jsonb)`/`word_morphology`/`ayah_meta`**: another untracked
  phantom trio, captured for migration 059's `REVOKE` target.
- **Fresh-CI-vs-live data preconditions**: migrations `080` and `090` each hardcode an
  exact set of historical row ids as an "abort if scope has drifted" precondition; on a
  fresh CI database (0 rows) these read NULL/0, which is not real drift. Tolerance
  substitutions preserve the real-apply precondition's teeth against any OTHER
  non-matching set.
- **Stale deferred-bedrock duplicates**: `migrations/infra/bedrock_substrate_deferred.sql`
  had accumulated ~25 stale duplicate `console_readonly` SELECT policies (of 27 total) —
  written when the bootstrap walk died long before migration 013 was ever reached, so the
  overlap with migrations 004/006/013/055 (which create those exact policies, each with
  its own `DROP POLICY IF EXISTS` guard) was never discovered until the walk finally got
  that far today. Removed; only `coordinator_panes_console_ro` and
  `invariant_registry_console_ro` were genuinely absent from the real chain.
  - Methodology lesson: re-audit deferred/bedrock files for staleness any time the walk
    reaches further than it did when the file was last authored — the same class of bug
    (`trg_agents_single_owner_repo_scope`, already fixed earlier this effort) can recur.
- **`escalate_full_tier_without_auditor`**: a live SECURITY DEFINER escalator that pages
  `cai`, never captured in any migration despite being security-sensitive (captured in
  an earlier segment of this same effort).
- **A dollar-quote-scanner desync bug** in `apply_migration.py`'s
  `strip_txn_control`/`_dollar_quote_spans` helpers surfaced while authoring these
  bedrock files — flagged separately to whoever owns that module.
