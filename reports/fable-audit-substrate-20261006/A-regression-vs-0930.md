## Five most consequential still-open items (ranked by silent-failure risk)

1. **Dead-man pagers still page through the pooler they report on** (finding 3 / item 2). The one mechanism meant to catch a breaker trip cannot speak during one; `pooler_breaker_snapshot.py` is also still untracked, so a fresh clone loses it silently. *Smallest fix:* move `_save(st)` above `_page`, wrap `_page` in try/except that spools `state/pending_page.json`, flush the spool on the next clear tick via `scripts/nazim_send.sh`/`tg_send.sh` (bot API, no pooler); `git add` script + plist. ~40 lines + 1 test.
2. **Escalation ladders still terminate at a possibly-dead console** (finding 10 / item 8). Today's 0 overdue P1s is because the console was alive all day, not because the ladder works. *Smallest fix:* `console_alive()` = fresh `agent_status` row for `orch-console` (<10 min) in `priority_sla_watchdog`, `sre_liveness_watchdog`, `wake_backstop_sweep` dead-foreign page; on False re-address P1+rr to `cc-orchestrator` (and the lease holder). Raise `SLA_MAX_VIOLATION_AGE_MIN` to ≥300 so P1 violations are actionable within the 240-min floor.
3. **Client-channel no-drop net is detect-only while a client has waited ~41h** (finding 12). The log literally says `WOULD page … waiting 2481m` for cosem-tdu. *Smallest fix:* flip `client-nodrop-watch` to page (it already computes the right target), cover the 2 missing channels, and give `tg_out.dead` (352 rows, +11/week) a consumer: replay-once-then-purge with a bus note.
4. **Stale-credential blast radius is still structural** (finding 5 / item 5). 54 `_dsn()` clones, no 28P01 path in the accessor, and the number of `.env.bak*` files holding the OLD password beside CURRENT secrets went 8 → 11. The next rotation reproduces the 09-29 breaker storm. *Smallest fix:* `connect_substrate()` in `substrate_dsn.py` (28P01 → re-read file → reconnect once → else `sys.exit(78)`), a parity test that fails CI on any new `def _dsn(`, and `shred` the 11 backups (they are not backups of anything current).
5. **launchd drift grew (56 untracked job names, incl. live singletons) and still has no parity test** (P1 drift row / item 7). A disk loss or fresh clone (the 09-05 shape) would silently drop `cc-orch`, `nazim-session`, `fleet-console`, `fleet-health`, `lane-wedge-watchdog`, `nazim-ingest`. *Smallest fix:* commit the live plists into `launchd/` (strip secrets — none embed any, verified 09-30), delete the `.bak/.disabled/.moved` litter from `~/Library/LaunchAgents/`, and a 30-line `launchd_drift_check.py` in cc-fleet-health that pages on label/ProgramArguments mismatch.
