## Findings (advisory / alert-not-block)
- **F1 — TEST-COVERAGE GAP [MEDIUM] (quality gate).** `test_self_recycle.py` (11 tests) has **zero** coverage of the new bash-seam wiring — neither the happy path (compaction runs before the detached reset is scheduled) nor the **`exit 6` fail-loud abort**. That abort guards the *higher-stakes singletons* (cai, nazim, fleet-health). Only the python/worker seam's abort is tested (I mutation-proved it). The dead-man's-switch this change exists for is shipped-but-untested on the singleton path. **Rec:** add a bash-level test (or thin harness) asserting (a) `exit 6` + reset NOT scheduled when the policy CLI returns rc3; (b) exit 0 + proceed on rc0 (no-op/held/warn). I verified the behavior manually today, but nothing catches a future regression.
- **F2 — cai-HOLD robustness [MEDIUM].** self_recycle passes `--session` only; add `--agent` (derivable from the RESET map: reset_cai.sh→cai, reset_nazim.sh→nazim, …) for dual-path parity with the policy design and the armed seam. Also: `COMPACTION_HELD` is **exact-string** match — fine for the suffix-free singleton `"cai"`, but it would **miss** a suffixed multi-instance lane id (`cc-irsyad-1`, `cc-irsyad-coord`) if a lane is ever added to the hold set — use component/prefix match at that point. (Same class as the lane_tasks self-accept suffix bypass I found on PR#75.)
- **F3 — ATOMIC WRITE [LOW-MED] (tool-level, newly load-bearing).** `compact_handoff_file` overwrites the handoff in place (`open(path,"w")` truncate+write) after the `.bak`. A crash mid-overwrite leaves the *live* handoff half-written; the abort correctly prevents booting onto it and the `.bak` preserves the original, but there is **no auto-rollback** and the on-disk handoff is left corrupted until manual recovery. For a recovery-critical path that now auto-fires, recommend temp-file + `os.replace` (atomic) so the live handoff is never observable half-written. Pre-existing in the already-cleared tool (#31821); the wiring elevates its importance.
- **F4 — NIT.** self_recycle recomputes `BYTES` after compaction but does not re-check the 800B floor; a handoff whose bulk is all in collapsible later sections (section[0] tiny) could drop <800B. Content is intact-compacted, not corrupt — benign. Optionally re-assert the floor post-compaction.
- **F5 — OPERATIONAL PRECONDITION (not a code defect).** Each tier enabled must keep current-state in section[0] (the verbatim-kept block). coord is covered by the always-keep-section[0] fix (tool review FINDING-1). Spot-check the worker lanes + fleet-health real handoffs have current-state in section[0] before/at their first over-cap fire.
