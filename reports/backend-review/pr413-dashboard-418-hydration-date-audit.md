## Non-blocking finding (Head-of-Quality, routed follow-up — does NOT block #413)
The bug was a **drifted duplicate** of a shared-formatter pattern; the class is systemic. A wide sweep of `src/app/dashboard/**` found **~49 tz-naive date formatters** (`new Date(x).toLocaleDateString/toLocaleString/toLocaleTimeString(…)` with **no** `timeZone`) across qurban / hr / pos / invoicing / school / reports / tabung / admin / cashier — each a **latent #418 sibling** wherever the component SSR-hydrates and the date can sit near a day boundary (Irsyad timestamps at `T16:00:00Z` = 00:00 SGT do). #413 fixes the one Elly hit; it does not address the siblings.

**Root gap:** the existing `check-hydration-safety.mjs` gate (in `lint:all`) flags bare `new Date()` / `Date.now()` / `window.` / `localStorage`, but **not** `new Date(x).toLocale*String()` without a `timeZone` — so this whole class is a **blind spot** (which is why #413's bug and the ~49 siblings pass CI; lint:all is EXIT 0). **Recommendation:** extend `check-hydration-safety.mjs` (or add a sibling `check-tz-naive-date-format`) to flag `.toLocale{Date,Time,}String(` on a Date in `.tsx` without a `timeZone` option, with the same `// hydration-safe-ignore` escape hatch — this would have caught #413 at CI and gives a gate-driven census to sweep the ~49. Routing to console/cai for prioritization (advisory; not a merge gate on #413).
