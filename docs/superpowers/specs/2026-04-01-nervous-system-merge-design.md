# Nervous System Merge — Design Spec

## Problem

The CTO Bot is reactive — it waits for messages and executes. It has no awareness of what's happening across repos between conversations, no proactive alerts, and no strategic thinking. Musa has to manually check status, remember blockers, and decide priorities.

## Solution

Merge the Wingmen Nervous System into the existing CTO Bot process. Add 5 scheduled tasks, 2 Supabase tables, a strategic CTO brain, and Islamic business principles as hard constraints.

## Architecture

```
CTO Bot Process (existing)
  ├── Telegram polling (reactive — messages, commands, photos, voice)
  ├── Agent dispatch (Router → Brainstorm/Auditor/Fixer)
  ├── Orchestrator integration (BUILD jobs)
  └── NEW: APScheduler (proactive)
       ├── brain_sync        — every 4 hours
       ├── morning_brief     — 6 AM SGT daily
       ├── weekly_digest     — Sunday 9 PM SGT
       ├── memory_sync       — midnight SGT daily
       └── session_compress  — 2 AM SGT daily
```

## Scheduled Tasks

### 1. brain_sync (every 4 hours)

Scans all active repos dynamically from REPOS.json.

**For each repo:**
- `git -C {local_path} log --oneline --since="24 hours ago"` — recent commits
- Read STATUS.md if present — extract phase, health, blockers, next up
- Count commits in last 24h and 7d
- Detect contradictions: STATUS.md says "deployed" but no commits in 14 days → flag stale

**After scanning all repos:**
- Query Supabase `jobs` table for active/queued jobs
- Query `clients` table for active clients
- Compile full snapshot as JSONB
- INSERT into `wingmen_brain` (append-only, never UPDATE)
- Generate `~/wingmen/BRAIN.md` (human-readable summary)
- Log run to `brain_sync_log`

**If a repo scan fails** (missing local path, git error): log the failure, set `scan_succeeded: false`, continue with other repos. Never let one repo break the whole sync.

### 2. morning_brief (6 AM SGT daily)

Reads the latest `wingmen_brain` snapshot and sends a strategic Telegram brief to Musa.

**Two parts:**

Part 1 — Status overview (generated from snapshot data):
```
☀️ Wingmen Morning Brief — 1 Apr 2026

🟢 ihsandms — 3 commits yesterday, deployed
🟢 cosem-tdu — stable, TDU POC pending onboarding
🟡 dookana — DB migration pending
⚪ hifz-companion — no activity (7 days)

Jobs: #9 running (ihsandms gamification)
Clients: TDU (active), ihsandms (Gazzabyte)
```

Part 2 — Strategic CTO analysis (generated by Claude):

Passes the snapshot to Claude with this prompt:
```
You are Musa's CTO — a Muslim technologist who thinks strategically about
both business growth and community impact. Given the current state:

1. What should Musa focus on today? (highest impact action)
2. What's at risk if nothing changes? (blockers aging, clients quiet)
3. What opportunity is being missed? (upsell, underserved clients)

Prioritize: revenue-generating work first (funds everything else),
then client satisfaction, then infrastructure, then open-source contributions.

Keep it to 3-5 bullet points. Be decisive, not diplomatic.
```

The combined brief is sent as one Telegram message.

### 3. weekly_digest (Sunday 9 PM SGT)

A longer strategic review sent via Telegram.

**Content (generated by Claude from the last 7 snapshots):**
- What shipped this week across all projects (commits, deploys, features)
- Client health: who's active, who's quiet, who needs attention
- Revenue signals: paying clients, pipeline opportunities, churn risk
- Technical debt accumulating (stale repos, failing tests, unresolved blockers)
- Recommendation: "Next week, focus on X because Y"
- Barakah check: "This week you contributed to [open-source/community work]. Keep it up." or "No community contributions this week — consider allocating time."

### 4. memory_sync (midnight SGT daily)

Diffs the latest two `wingmen_brain` snapshots.

**Flags significant changes:**
- New repo added to REPOS.json
- Repo status flipped (active → paused, or vice versa)
- New client onboarded
- Revenue signal appeared or disappeared
- Health degraded (green → yellow → red)

**Writes a summary to `brain_sync_log`** with `task_name: "memory_sync"` and the diff details. This log is what claude.ai reads via Supabase MCP to stay contextually aware without manual updates.

### 5. session_compress (2 AM SGT daily)

Writes `~/wingmen/SESSION_CHECKPOINT.md` with:
- Current orchestrator job queue (from Supabase `jobs` table)
- Active clients and their repos
- Pending fixes (`_pending_fixes` dict state — serialized)
- Last brain_sync timestamp
- Any running Claude CLI subprocesses

This file is read by the bot on startup for context recovery after Mac Mini restarts.

## Database Tables

Added to the existing cto-bot Supabase project (`tscuymavysscrvoberrr`):

### wingmen_brain (append-only)

```sql
CREATE TABLE wingmen_brain (
    id BIGSERIAL PRIMARY KEY,
    snapshot_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    repos JSONB NOT NULL,
    job_queue JSONB,
    clients JSONB,
    sync_health TEXT NOT NULL DEFAULT 'healthy',
    context_notes TEXT,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX idx_wingmen_brain_snapshot_at ON wingmen_brain(snapshot_at DESC);
```

**Retention:** Delete snapshots older than 30 days (cleanup in brain_sync).

### brain_sync_log (audit trail)

```sql
CREATE TABLE brain_sync_log (
    id BIGSERIAL PRIMARY KEY,
    task_name TEXT NOT NULL,
    status TEXT NOT NULL DEFAULT 'success',
    duration_ms INTEGER,
    details TEXT,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

## CTO Principles (Hard Constraints)

A new file `CTO_PRINCIPLES.md` loaded into the Brainstorm Agent's system prompt for admin users and into the morning_brief/weekly_digest Claude prompts.

```markdown
# CTO Principles — Wingmen

## Business Priorities (in order)
1. Revenue-generating work — it funds everything else
2. Client satisfaction — deliver what was promised
3. Infrastructure — make the system more reliable and efficient
4. Open-source / community — waqf for the ummah

## Islamic Constraints (non-negotiable)
- Halal revenue only — no riba (interest), no gambling mechanics, no deceptive practices
- Zakat transparency — any system handling zakat must be fully auditable
- Amanah (trust) — client data is a trust, not an asset. Minimize collection, maximize protection.
- No vendor lock-in that traps clients — they should be able to leave with their data
- Waqf mindset — open-source contributions are sadaqah jariyah (ongoing charity)

## Decision Framework
- When in doubt, choose the simpler solution
- When two options have equal merit, choose the one that helps more people
- When choosing between speed and correctness, choose correctness for anything touching money or knowledge
- When choosing between profit and community impact, find the path that serves both

## What the CTO Should Flag
- Clients going quiet (>7 days no interaction) — proactive check-in needed
- Revenue concentration risk (>50% from one client)
- Technical debt aging (>2 weeks unaddressed)
- Open-source repos without recent contribution (waqf neglect)
- Any architecture decision that creates dependency on a single provider
```

## Integration with Existing Systems

### Brainstorm Agent (modified)
When `is_admin(user)`, the brainstorm agent's system prompt includes CTO_PRINCIPLES.md content. This makes strategic conversations principle-guided.

### Morning Brief → Actionable
The morning brief doesn't just report — it recommends. Musa reads it at 6 AM and knows exactly what to work on.

### Weekly Digest → Accountability
The Sunday digest creates a natural weekly rhythm: review what shipped, assess what matters, plan the next week. The barakah check ensures community work doesn't get forgotten.

### BRAIN.md → Context for Any Session
Any new Claude Code session can read `~/wingmen/BRAIN.md` to instantly understand the state of all projects without scanning anything.

## Success Criteria

1. brain_sync runs every 4h, scans all active repos, writes snapshot to Supabase
2. morning_brief sends at 6 AM SGT with status + strategic recommendations
3. weekly_digest sends Sunday 9 PM SGT with week review + next week focus
4. memory_sync detects significant changes and logs them
5. session_compress writes checkpoint file for context recovery
6. BRAIN.md is auto-generated and always current
7. CTO principles guide strategic recommendations (halal, amanah, waqf)
8. No degradation of existing reactive bot functionality
9. Scheduler failures don't crash the bot — graceful degradation
10. New repos added to REPOS.json are automatically picked up by next brain_sync
